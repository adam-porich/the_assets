# 04 — Build direct candidate-to-card framing

## Outcome

Turn “Use this portrait” into a direct visual path:

```text
benchmark result → card preview → drag/zoom → keep card
```

The user does not create a portrait master, choose raw/clean/final, enter an
ID, or edit face/head/shoulder/silhouette geometry. The selected full-resolution
run output remains the reusable art source, and a small card draft records only
its provenance and visible framing.

## Card draft contract

Store draft metadata in `portrait-library/cards/cards.json` and rendered images
beside it. A record contains:

```json
{
  "card_id": "opaque-id",
  "run_id": "...",
  "run_item_id": "...",
  "label": "Experimental claimant",
  "template_id": "estate-card-v1",
  "archetype": "bust",
  "framing": { "zoom": 1.0, "offset_x": 0.0, "offset_y": 0.0 },
  "decision": "working",
  "render_path": "cards/<id>.png",
  "created_at": "...",
  "updated_at": "..."
}
```

IDs are generated by the service. `decision` is only `working`, `keep`, or
`discard`; it is an exploratory choice, not a production approval gate.

Use one framing formula in TypeScript and Python:

- Calculate the base scale that covers the art window with the source image.
- Multiply it by `zoom` (`1` is minimum cover).
- Centre the scaled image, then add `offset_x * art_window_width` and
  `offset_y * art_window_height`; positive offsets move right/down.
- Clamp offsets so no empty pixels enter the art window.

Keep the formula small and test it with shared numeric fixtures. The browser
provides immediate visual movement; the Pillow render made on pointer release
or a short debounce is the saved source of truth.

## Checklist

- [ ] Replace the current archetype contract with three artist-facing framing
  presets labelled **Bust**, **Tall**, and **Torso**. Each preset supplies an
  initial zoom/offset only; determine useful defaults against several
  landscape benchmark outputs.
- [ ] Remove face targets, safety bands, head boxes, shoulder lines, silhouette
  boxes, and preferred-archetype state from the new renderer. They are not
  needed for direct manipulation.
- [ ] Implement draft create/list/read/update operations. Creating from a run
  item chooses its single full-resolution painterly output, generates the ID,
  applies the Bust default, renders the card, and returns its workbench URL in
  one action.
- [ ] Update the Pillow card renderer to read a run item directly and apply the
  shared zoom/offset formula. Preserve the current lightweight card frame and
  336×276 art window as the evaluation environment.
- [ ] Make draft writes and image renders replace the previous draft
  atomically. A failed render must leave the last good card preview and record
  intact.
- [ ] Build a dedicated Card Workbench view with one large card preview, a
  source-result thumbnail, Bust/Tall/Torso buttons, drag-to-position, a zoom
  slider, reset, editable card label, and Keep/Discard actions.
- [ ] Support pointer and keyboard operation. Arrow keys nudge the image, plus
  modifiers make small/large adjustments, and the selected controls have
  visible focus states.
- [ ] Save framing automatically on pointer release, keyboard adjustment, and
  debounced zoom. Show saving/saved/error state next to the preview; do not add
  a geometry form or a required Save button.
- [ ] Keep a collapsible details drawer for source provenance, run/recipe
  snapshot, reference thumbnails, output dimensions, and the numeric framing
  transform. These details must not interrupt the normal path.
- [ ] Add an optional visual debug overlay for the art-window boundary,
  centre-lines, and image bounds. Do not restore semantic anchor/box editing.
- [ ] Add a compact card-draft gallery reachable from the application shell.
  Default to kept/working cards, allow discarded cards to be revealed, and
  reopen any draft at its saved framing. Do not recreate sets or batch
  approvals.
- [ ] From the Card Workbench, provide clear “Back to run” and “Try another
  result” actions so framing remains part of the experiment loop.
- [ ] Add Python tests for cover scale, offset clamping, deterministic render,
  draft provenance, atomic update failure, preset switching, and missing run
  items.
- [ ] Add UI tests for Use this portrait, drag/zoom persistence, archetype reset,
  save feedback, refresh/reopen, keyboard nudging, Keep, and back navigation.

## Acceptance checks

- [ ] Clicking “Use this portrait” opens a rendered card without any prompt,
  ID field, source-kind choice, or intermediate promotion screen.
- [ ] Dragging and zooming visibly updates the portrait inside the art window,
  persists automatically, and matches the saved Pillow render after refresh.
- [ ] Bust, Tall, and Torso provide meaningfully different starting frames and
  remain freely adjustable.
- [ ] A kept card can be reopened from the gallery and traced to its source,
  run, recipe, and references from the details drawer.
- [ ] No master, anchor, approval, validation, or set concept is required to
  create and keep a card.
- [ ] Python tests, UI tests, and `npm run build` pass.

## Out of scope

- Production card layout, rules text, print export, approved sets, automated
  composition scoring, and multi-card validation.
- Image editing beyond crop/position/scale. Regeneration belongs in Style Lab.
- Mobile-first precision editing; the page should remain viewable on small
  screens, but desktop pointer/keyboard use is the primary experiment.
